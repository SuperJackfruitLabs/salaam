# Local autonomy contract assessment

Scope: Salaam local operator permission configuration and local edit decision source, implemented on `feat/local-pi-parity` from `20f7175`. This adds no AgentPod/Toolkit/ACP authority token, issuer, audience, station capability, or external grant. Charter revision inspected: `f3a7652392ff967c5da7e297099a7cb64a30e5dc`. The decided capability distinction (2026-09-02) separates discoverable skill, invocable affordance and execution authority; the decided human-terminal record (2026-09-18) does not justify manufacturing product grants from a terminal preference. This implementation preserves those distinctions; it does not amend either agreement.

Producer: controller-authenticated `POST /v1/sessions/:id/permissions`, with stable request ID, expected policy revision and strict mode/path schema. Root is derived from the admitted session, never supplied by a worker. Omitted policy records default to review for local coding and inspect for inspection-only sessions. Unknown policy keys, unsupported scopes and missing coding authority are rejected. An old daemon returns an unsupported route; the TUI never treats that as configured permission.

Persistence: `permissions.configured` and the cached request response commit together through Store. The first permission configuration atomically advances the schema marker to 28. Prior binaries support only through 27 and reject the state directory instead of silently ignoring its restrictions. Unconfigured state retains schema 27. Auto-decisions are recorded as `permission.auto-approved` with `decided_by=scoped-policy` in the existing approval ledger. Native provider/worker protocols are unchanged. Model-supplied local tool arguments cannot configure policy.

Consumers: LocalCoding checks the policy before preparation and execution; ManagedWork retains its exact binding, epoch, expiry, owner and permission consumption checks. The house extension already accepts decided approvals, so no UI confirmation is forged. Policy revision changes invalidate unused automatic decisions. Local undo also respects inspect mode. TaskDriver and task budget contracts are unchanged; progression uses their existing APIs and cannot alter permissions. Managed stations, external harnesses and child workers receive no new authority.

Tests: unit autonomy cases cover scope boundaries, explicit shell review, missing capability, foreign control, symlinks/private paths, revision conflicts, saved-request replay, changed bytes, epoch changes, revocation, expiry, budget rejection and uncertain native ownership. The real pinned Pi proof checks actual auto-edited files, records the decision source, restarts the daemon, and confirms shell work still waits for review. Existing managed-operation, local coding, task-policy/task-budget, task recovery and terminal suites are regression consumers. These are local/offline proofs, not a live fleet or adversarial OS sandbox proof. No cross-product shared corpus was changed or claimed exercised.

Rollout: rebuild and restart an idle daemon to enable the new operator routes. Existing sessions remain at their previous manual-review behavior until explicitly configured. After the first policy configuration, downgrade is rejected by the prior schema guard. Restore a compatible pre-configuration backup only through an explicit operator recovery procedure; never lower the schema marker to bypass it.
